# Dependency security review, 2026-10-12

React, React DOM and react-server-dom-webpack are pinned together at 19.2.8. This is an explicitly patched version for CVE-2026-44907 / GHSA-wx67-qw84-cm4g, whose affected 19.2 range ends at 19.2.7. Current npm audit reports no React/RSC advisory. Moving to 19.3.0 is not required for that fix; React recommends pinning framework/bundler RSC dependencies because their internal APIs can change across minors.

- https://github.com/react/react/security/advisories/GHSA-wx67-qw84-cm4g
- https://react.dev/reference/rsc/server-components

Next was patched from 16.3.1 to 16.3.8 without a minor-version jump. The package supplies NextAuth's peer and types; vinext owns the deployed server and `next/*` shims. The app does not use Next's native image optimizer, `next/og`, Draft Mode or `use cache`, and the Worker is not a Windows Next server. Even though those reported critical paths were not the app's execution path, the same-minor package fix removes their audit findings. Playwright was patched from 1.55.0 to 1.55.1 for its browser-download TLS verification fix.

The current frontend uses Privy 3.48.1 and viem 2.56.5; Thirdweb and its TOML/YAML tooling chains have been removed. The clean npm 10.9.4 lock also pins date-fns 4.4.0 to satisfy Base UI's optional peer without replacing MetaMask's separate date-fns 2.30.0 dependency. This resolves clean-install placement, not a security advisory.

The final full audit reports **55 affected package entries: 2 critical, 9 high, 43 moderate and 1 low**. Filtering its affected nodes against the final lock's production/development markers leaves **45 production package entries: 0 critical, 9 high and 36 moderate**. Ancestor entries repeat the same underlying advisories. No React/RSC, Next, NextAuth, or direct viem finding remains in this audit. This is a bounded dependency-path assessment, not a claim that the graph is advisory-free or that every SDK feature has been exercised.

No currently exercised high-severity request path was identified. Some affected Node transport implementations are bundled in Worker SSR chunks, so the remaining findings must not all be described as development-only.

The two critical full-audit entries are form-data 2.3.3 and its ancestor request 2.88.2 in the unused development chain truffle-flattener → resolver-engine → request. This chain also accounts for development-only qs, tough-cookie and UUID findings. The site build, authentication and request handlers do not run the Solidity flattener. Preserve these as unresolved development-tool risks; do not present them as remediated. No forced flattener downgrade was applied. [Form-data advisory](https://github.com/form-data/form-data/security/advisories/GHSA-fjxv-7rqg-78g4).

The additional low finding is Babel 7.29.0 source-map file disclosure when compiling attacker-controlled source that the attacker can then read. W3RK compiles repository source, not arbitrary visitor code. Babel 7.29.6+ fixes it; npm suggests 7.29.7. This is a small future tooling update, not a visitor request-path finding. [Maintainer advisory](https://github.com/babel/babel/security/advisories/GHSA-4x5r-pxfx-6jf8).

No dependency changes were made for this review. Do not run `npm audit fix --force`: its Privy 3.6.1 and vinext 0.2.1 suggestions are downgrades. Future narrow candidates include Babel 7.29.7, the audit-suggested same-major ethers 6.17.0 update, and fflate 0.7.5 with compatibility checks. Cross-major Undici, Busboy, UUID, stream-json, and decode-uri overrides need separate evidence.
